# forms merger

Helper scripts that **prepare input for the main GST tool**. The GST portal
only lets you download one Excel workbook per return type per tax period
(month or quarter). Before a GSTIN's data can be scrutinised by the main GST
tool across a full financial year, all of those single-period downloads for
a given return type need to be consolidated into one workbook. That is what
everything under this tree does: each subfolder is a small, self-contained
Python "merger" for one GST return type, run against a folder of downloaded
`.xlsx` files, producing one `*_Merged.xlsx` output file for that return
type.

None of these scripts perform any GST scrutiny/analysis themselves — they
only detect, sort, and concatenate/consolidate source workbooks. The merged
output feeds into the separate "main gst tool".

## Structure

```
forms merger/
└── merger-tool/                   <- see merger-tool/README.md
    ├── run_all_gst_merge.bat      <- master orchestrator
    ├── gstr1/
    ├── gstr2a/
    ├── gstr2b/
    ├── gstr3b/
    └── e invoice/
```

## Return-type subfolders

| Folder | Return type | Merge script | Output file |
|---|---|---|---|
| `merger-tool/gstr1/` | GSTR-1 (outward supplies) | `merge_gstr1.py` | `GSTR1_Merged.xlsx` |
| `merger-tool/gstr2a/` | GSTR-2A / R2A (auto-drafted ITC statement) | `merge_r2a.py` | `R2A_Merged.xlsx` |
| `merger-tool/gstr2b/` | GSTR-2B (static monthly/quarterly ITC statement) | `merge_gstr2b.py` | `GSTR2B_Merged.xlsx` |
| `merger-tool/gstr3b/` | GSTR-3B (summary return) | `merge_gstr3b.py` | `GSTR3B_Merged.xlsx` |
| `merger-tool/e invoice/` | E-Invoice auto-drafted GSTR-1 | `merge_einv.py` | `EINV_Merged.xlsx` |

Each of these folders is built the same way: a private copy of the shared
helper module `gst_merge_common.py` sits next to one `merge_*.py` script.
Every script auto-detects its input files by workbook content (sheet-name
signature), not by filename, sorts them chronologically by tax period, and
writes its merged output into the same folder it was run from. See each
subfolder's own README for exact input/output details.

Details on the orchestrator (`run_all_gst_merge.bat`) are in
`merger-tool/README.md`.

> Two dead-code duplicates that used to live in this tree — a stray
> top-level `gst_merge_common.py` and an unused top-level
> `merger-tool/merge_gstr3b.py` — have been removed. Neither was referenced
> by `run_all_gst_merge.bat` or any other script.

## Observed stray output files

Several subfolders (`gstr1/`, `gstr2b/`, `gstr3b/`) contain `*_Merged.xlsx`
files that are not the return type that folder's own script produces (e.g.
`gstr3b/` contains `EINV_Merged.xlsx`, `GSTR1_Merged.xlsx`, and
`GSTR2B_Merged.xlsx` in addition to its own `GSTR3B_Merged.xlsx`). These
look like merged outputs copied there manually (e.g. to stage all five
merged workbooks for one GSTIN together before feeding them into the main
GST tool) rather than anything generated by the scripts themselves — no
script in this tree writes an output file into any folder other than its
own current working directory.
